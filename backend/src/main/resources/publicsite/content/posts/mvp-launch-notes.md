# 一天上线个人主页 MVP：架构与取舍

> 本文记录个人主页 MVP 上线过程中的关键架构决策，供后续维护者理解为什么是现在的样子。

## 为什么不需要数据库

MVP 的公开内容（公开介绍、精选作品、博客文章）都是低频、小体量的数据，且全部随仓库版本化。

- 结构化的元数据使用 JSON 文件，构建时校验必填字段；
- 博客正文使用 Markdown 文件，禁用原始 HTML；
- Spring Boot API 匿名、只读，启动时不依赖 MySQL 或嵌入式数据库。

这样首发阶段没有数据库成本，也没有数据迁移负担；内容更新走代码评审，天然保留历史。

## 隔离的公开站点应用

旧应用包含账户、JWT、聊天、在线编程和计划等实验功能。MVP 建立了一个**隔离的公开站点应用切片**：

```java
@SpringBootApplication(
    scanBasePackages = "com.myblog.publicsite",
    exclude = { ... DataSourceAutoConfiguration, SecurityAutoConfiguration ... })
```

它只扫描 `com.myblog.publicsite` 下的组件，并排除数据源与安全自动配置，因此：

- 不加载旧账户控制器、JWT 过滤器、Mapper 或依赖数据库的服务；
- 生产进程在没有 MySQL 的情况下正常启动；
- 注册、登录和 JWT 过滤器不激活，公共接口全部匿名开放。

## 冷启动与重试

Render 免费 API 会在一段时间闲置后休眠，首次请求通常需要约一分钟唤醒。因此前端在请求内容时：

1. 静态导航和四区骨架立即渲染；
2. 三秒未取得内容时，提示“免费内容服务正在启动，通常可能需要约一分钟”；
3. 幂等请求在不超过 75 秒的窗口内有限重试；
4. 最终失败后显示手动重试按钮，同时保留导航、邮箱和 GitHub 入口。

## 隐私边界

页面只展示技术方向、技能和技术栈，不公开位置、机会状态、简历、肖像或经历时间线。所有内容上线前必须经站点所有者确认。

## 发布流程

先 API，后前端，再把最终前端来源写入 API 并重新部署，最后完成桌面／移动、热启动／冷启动冒烟测试。详见仓库根目录部署文档。

```bash
# 本地启动公开站点 API（Java 11 + Spring Boot 2.7）
java -jar backend/target/backend-0.0.1-SNAPSHOT.jar
```
