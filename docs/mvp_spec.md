# 基于 A+C 原型的一天上线个人主页 MVP 最终规格

状态：**基于原型重新锁定，可直接进入实施**  
原型来源：`codex/prototype-mvp-homepage`，提交 `7969f93`；公开决策见 [原型票据 #2](https://github.com/hxc236/myblog/issues/2)  
视觉契约：[个人主页 MVP 最终设计规范](./Design.md)  
部署决策：[选择 Vue 与 Spring Boot 的一天部署平台](https://github.com/hxc236/myblog/issues/3)

## 问题陈述

当前仓库是一个早期 Spring Boot + Vue 应用，包含账户、聊天、在线编程和计划等实验功能，但还不是一个可以公开使用的个人主页。访客无法在首屏理解站点所有者的技术方向，无法用一致的方式查看精选作品和博客，也缺少直接、可信的联系与 GitHub 入口。

仓库还存在一天上线的工程障碍：Java／Spring 依赖混用不兼容版本，前端写死本地服务地址，后端启动依赖数据库，活动配置中存在已提交秘密，现有认证和旧功能会扩大生产运行面。

三个可切换首页原型已经回答了视觉方向问题，但原型本身包含占位内容、淘汰方案和不再适用的个人资料元素。需要把已确认的“A 整体 + C 作品区”以及 Q8 的隐私边界转换为唯一、可测试、可部署的生产规格，并在一个工作日内上线。

## 解决方案

构建一个中文优先、响应式、无需登录的个人主页 MVP，保持 Vue 3 + Spring Boot 2.7 的前后端分离结构。

首页使用方案 A 的暖色编辑式视觉、浮动导航、中文衬线 Hero、博客列表和深色联系页脚；作品区使用方案 C 的全宽工程档案行，并转译到 A 的浅色视觉系统。首页除导航与页脚元信息外只包含四个一级内容区：

1. 公开介绍（Hero）：不涉及隐私的技术方向、技能和技术栈；
2. 作品展示：三个真实精选作品；
3. 博客：首页近期文章，以及独立列表／详情路由；
4. 联系方式：已验证邮箱、GitHub 和版权标识。

取消独立个人资料功能。MVP 不公开位置、机会状态、简历、肖像、经历时间线或其他个人事实。GitHub 在首屏和联系区均提供明确入口。

内容由随仓库版本化的 JSON 和 Markdown 驱动，经匿名只读 Spring Boot API 提供。MVP 不使用外部运行时数据库，不激活旧账户和 JWT 流程，不建设管理后台。Vue 静态站点与 Java 11 API 分别部署到 Render 的 HTTPS 平台子域名，并处理免费 API 的冷启动。

39. 作为后续维护者，我希望旧账户、聊天、在线编程和计划功能不进入 MVP 运行时，以免扩大风险与工期。
40. 作为后续维护者，我希望管理后台和数据库 CRUD 明确属于第二阶段，以便先根据 MVP 和博客工作流反馈再设计。

## 实施决策

### 1. 原型是决策证据，不是生产代码

- 方案 A 决定全局视觉、导航、Hero 排版、按钮语言、博客列表和联系页脚。
- 方案 C 只决定作品区的信息架构：编号、标题、成果、职责、技术栈、年份和外部操作。
- 方案 C 的作品行必须适配方案 A 的 Paper、Surface、Ink、Forest 色彩和字体系统。
- 方案 A 的资料卡必须替换为技能／技术栈面板；位置、机会状态、肖像、数字指标和独立 About 不进入生产。
- 方案 B、方案切换器、查询参数变体、占位邮箱、占位作品和占位博客不进入生产。
- 实施应重写唯一最终页面，不合并或直接发布原型分支。

### 2. 页面与路由

- `/` 是唯一首页，按公开介绍、作品展示、博客、联系方式顺序渲染四个内容区。
- Hero 对应首页 `#intro`，不是独立路由。
- 作品、博客和联系分别使用 `#work`、`#writing`、`#contact`。
- `/blog` 展示全部博客文章。
- `/blog/:slug` 展示单篇博客文章。
- 未知路由显示站内 404。
- Vue Router 使用 history 模式；生产托管将非静态资源路径重写到应用入口。
- 旧 `/home/`、`/news/`、`/chatroom/`、`/coding/`、登录和注册入口不出现在生产导航；可重定向首页或由站内 404 处理，但不得激活旧功能。

### 3. 导航与首页布局

- 桌面导航继承 A 原型：固定、居中、浅色半透明表面，距离顶部约 16 像素。
- 导航包含公开站点标识、四个首页锚点、GitHub 外链和联系入口。
- 720 像素以下隐藏中间锚点，保留站点标识、GitHub 与联系入口。
- Hero 桌面端使用不对称双栏；左栏为技术价值主张和行动，右栏为技能／技术栈面板。
- 900 像素以下 Hero 改为单栏，先介绍与按钮，再技能面板。
- 主行动滚动到作品；次行动打开邮箱；GitHub 在首屏可见。
- 首页不得新增独立 About、工作原则、经历、统计数字或第五个内容区。

### 4. 内容契约

所有内容归站点所有者所有，随仓库版本管理。结构化元数据使用 JSON，博客正文使用 Markdown；Markdown 禁止原始 HTML。构建时校验必填内容，不允许用原型占位数据补齐。

#### 4.1 公开介绍（Public Introduction）

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `displayName` | 是 | 可公开称呼或标识，不要求真实姓名 |
| `eyebrow` | 是 | 简短技术栈眉题，例如 Java／Spring Boot／Vue |
| `headline` | 是 | 中文技术价值主张 |
| `introduction` | 是 | 不涉及隐私的第一人称技术介绍 |
| `skillGroups` | 是 | 有顺序的后端、前端、交付技能分组 |
| `email` | 是 | 已验证的公开联系邮箱 |
| `githubUrl` | 是 | 已验证的 GitHub 主页 |
| `copyright` | 是 | 页脚版权标识 |

禁止增加 `location`、`timezone`、`availability`、`resumeUrl`、`portrait`、生日、电话、住址、工作经历或主观熟练度字段。第二阶段如需引入，必须重新评审隐私边界。

#### 4.2 作品（Project）

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `key` | 是 | 稳定内部标识 |
| `title` | 是 | 作品标题 |
| `summary` | 是 | 一句话成果或解决的问题 |
| `role` | 是 | 站点所有者的真实职责 |
| `stack` | 是 | 有顺序的相关技术列表 |
| `year` | 是 | 完成或进行年份 |
| `repositoryUrl` | 否 | 已验证公开仓库 |
| `demoUrl` | 否 | 已验证在线演示 |
| `featuredOrder` | 是 | 首页展示顺序 |

首发必须恰好三个作品。每个作品至少有一个已验证外部目标；没有目标的占位作品阻止发布。MVP 不建设站内作品详情页。

#### 4.3 博客文章（Blog Post）

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `slug` | 是 | 稳定且适合 URL 的标识 |
| `title` | 是 | 文章标题 |
| `summary` | 是 | 列表摘要 |
| `publishedAt` | 是 | ISO 日期 |
| `readingMinutes` | 是 | 正整数阅读时长估计 |
| `featured` | 是 | 是否可在首页展示 |
| `bodyResource` | 是 | Markdown 正文资源标识 |

首发目标为一至三篇真实博客。即使只有一篇，列表和详情仍上线；不得虚构文章填充数量。

### 5. 公开 API 契约

成功响应统一使用 JSON 与 UTF-8。内容接口匿名、只读，可返回短时公共缓存头。不存在的资源返回 JSON 404，不返回认证挑战或通用服务器错误。

| 方法与路径 | 响应 |
| --- | --- |
| `GET /api/v1/introduction` | 一个 Public Introduction |
| `GET /api/v1/projects` | 按 `featuredOrder` 排序的三个 Project |
| `GET /api/v1/posts` | 按日期倒序的 Blog Post 元数据，不含正文 |
| `GET /api/v1/posts/{slug}` | Blog Post 元数据与 Markdown 正文 |
| `GET /api/v1/health` | 最小就绪状态 |

规则：

- MVP 仅支持 `GET`、`HEAD` 和预检需要的 `OPTIONS`。
- 格式错误或不存在的 `slug` 返回 404。
- 无效必填内容使测试与构建失败，不在运行时静默忽略。
- API 不返回秘密、本地文件系统细节、账户数据、旧领域实体或被禁止的个人资料字段。
- 公开介绍和作品可使用五分钟公共缓存；健康接口不缓存。

### 6. 前端数据与状态

- 统一 API 客户端从 `VUE_APP_API_BASE_URL` 读取 API 来源，不写死 localhost。
- 首页数据获取不依赖 Vuex 登录状态，不携带认证凭据。
- 静态导航、四区布局和中性骨架立即渲染。
- 三秒未取得内容时显示“免费内容服务正在启动，通常可能需要约一分钟”的等义提示。
- 幂等请求使用有上限的延迟重试，总窗口不超过 75 秒。
- 最终失败后显示手动重试，同时保留静态导航、邮箱和 GitHub。
- Markdown 渲染支持标题、列表、链接、引用、行内代码和围栏代码块，禁用原始 HTML。
- 外部链接使用安全的新窗口行为并清楚说明目标。

### 7. 响应式与无障碍

- 主要布局断点为 900 像素；移动排版断点为 620 像素；导航折叠点约 720 像素。
- 390 像素到宽屏桌面端不得出现横向滚动。
- C 风格作品档案在窄屏改为堆叠，职责与技术栈不得隐藏。
- 每个页面只有一个页面级主标题，章节标题层级连续。
- 导航、按钮、作品、博客、GitHub、邮箱和重试入口可使用键盘操作并具有可见焦点。
- 触控目标尽量达到 44 × 44 像素，颜色对比满足 WCAG AA。
- 尊重 `prefers-reduced-motion`，装饰元素对辅助技术隐藏。

### 8. 后端运行时边界

- Spring Boot 保持 2.7 系列，统一到 Spring Boot 2.7.18，运行于 Java 11。
- 移除显式 Spring 3 starter 版本覆盖，由 Boot 父项目管理兼容依赖。
- 建立隔离的公开站点应用切片，只扫描新的公共内容组件并排除数据源自动配置。
- MVP 应用上下文不加载旧账户控制器、JWT 过滤器、数据库 Mapper 或依赖数据库的服务。
- 生产进程在没有 MySQL 和嵌入式数据库的情况下启动。
- Maven 打包和 Docker 运行以隔离公开站点应用为可执行入口。
- 除非旧代码阻止编译，不对旧模块做大范围重构或删除。

### 9. 安全与配置

- 从活动配置移除所有已提交数据库密码和 JWT 签名材料，并在上线前轮换已暴露值。
- 运行时配置来自环境变量；前端变量不得包含 Render 凭据或其他秘密。
- `VUE_APP_API_BASE_URL` 只保存公开 API 来源。
- `SITE_ORIGIN` 保存准确的生产前端来源。
- 生产 CORS 只允许该准确来源，关闭凭据，并限制方法与请求头。
- 本地开发来源只存在于开发配置，不得成为生产通配符。
- 公共内容和健康接口匿名开放；注册、登录和 JWT 过滤器不激活。
- 错误响应不暴露堆栈、文件位置、环境变量或内容内部细节。

### 10. 构建与实施顺序

1. 使用独立实施 worktree 或明确检查点保护当前脏工作区。
2. 在本地和 Docker 统一 Java 11，并修复失效的本地 Java 环境指向。
3. 对齐 Spring Boot 2.7.18 和 starter 依赖。
4. 建立无需数据库的隔离公开站点应用。
5. 实现内容模型、校验、资源读取、五个公开接口、安全／CORS 和健康检查。
6. 重写唯一生产首页，实现 A 整体、C 作品行、博客路由与冷启动状态。
7. 使用经确认的真实内容替换全部原型占位内容。
8. 完成 Java 11 多阶段 Docker 构建与前端生产构建。
9. 在创建托管服务前通过全部本地发布检查。

### 11. Render 部署

前后端从同一个 GitHub 仓库分别部署到 Render。

#### API Web Service

- 使用 Docker，Java 11 构建阶段与 Java 11 运行阶段。
- 区域为新加坡，首发使用 Free 预览层级。
- 使用 Render 提供的 `PORT`。
- 健康路径为 `/api/v1/health`。
- 前端 URL 确定后设置 `SITE_ORIGIN`。

#### Vue Static Site

- 依照 lockfile 安装依赖并执行生产构建。
- 发布 Vue CLI 的生产输出。
- 构建变量 `VUE_APP_API_BASE_URL` 指向 Render API 的 HTTPS 来源。
- 所有非静态资源路由重写到应用入口。

部署顺序：先 API，后前端，再把最终前端来源写入 API 并重新部署，最后完成桌面／移动、热启动／冷启动冒烟测试。

接受 Free API 闲置休眠和约一分钟唤醒时间。当求职投递期的第一印象受到影响时，升级为持续在线实例。

## 测试决策

### 主要自动化测试接缝

沿用已确认的单一高层后端接缝：针对隔离公开站点应用执行 `SpringBootTest + MockMvc`。测试只验证通过 HTTP 可观察的行为，覆盖路由、内容读取与校验、序列化、匿名安全、CORS、缓存和错误映射；不为资源读取器或控制器内部实现重复增加低层测试。

必须自动验证：

- 公开介绍接口返回所有必填字段，并且不返回位置、机会状态、简历、肖像或经历字段。
- 作品接口按配置顺序返回恰好三个作品，每个至少有一个外链。
- 博客列表不含正文并按日期倒序。
- 已知博客详情返回元数据与 Markdown 正文。
- 不存在或格式错误的 `slug` 返回 404。
- 健康接口无需数据库即可返回就绪。
- 公共接口不需要认证或凭据。
- 准确生产来源通过 CORS，无关来源不会被动态回显。
- 无效必填内容导致测试失败。

仓库现有应用上下文测试可作为启动 Spring 的先例，但必须改为指向隔离公开站点应用，并扩展到 HTTP 行为。

### 前端与视觉接缝

一天 MVP 不新增组件测试框架。必须通过：

- 按 lockfile 安装依赖；
- lint 与生产构建；
- 常规宽屏桌面和 390 像素移动端视觉冒烟；
- 首页只有四个一级内容区；
- A 的全局风格和 C 的作品档案行均能被清楚识别；
- 不出现资料卡、位置、机会状态、原型切换器或淘汰方案；
- 键盘可操作导航、邮箱、GitHub、作品、博客和重试按钮；
- 页面无横向溢出，浏览器控制台无错误；
- `/blog`、真实博客 URL 和未知路由均可直接打开并刷新；
- 加载、冷启动、自动恢复和最终失败状态可理解且可操作。

### 线上验收

- 前后端地址均为 HTTPS，HTTP 自动跳转 HTTPS。
- API 使用 Render 端口启动并通过健康检查。
- 前端只请求 Render API 的 HTTPS 来源。
- CORS 只接受准确前端来源。
- 浏览器控制台无混合内容、CORS、认证或 JavaScript 错误。
- API 闲置至少 15 分钟后，页面能解释唤醒延迟并自动恢复。
- 所有可见内容和外部链接均经站点所有者确认。
