# 个人主页 MVP 最终设计规范

状态：**基于原型重新锁定，可进入实施**  
原型来源：`codex/prototype-mvp-homepage`，提交 `7969f93`；公开决策见 [原型票据 #2](https://github.com/hxc236/myblog/issues/2)  
原型选择：**方案 A 的整体视觉与页面节奏 + 方案 C 的作品档案行**  
范围修订：Q8 取消个人资料，首页仅保留公开介绍、作品展示、博客、联系方式四个内容区。

## 1. 设计结论

生产页面不是对任一原型的直接复制，而是一次明确的合成：

- 从方案 A 保留暖色纸张背景、浅色浮动导航、中文衬线大标题、克制的绿色强调、作品优先行动入口、博客分隔行和深色联系页脚。
- 从方案 C 仅保留全宽横向作品档案行，以及“作品是成果记录，不是仓库列表”的信息组织方式。
- 用隐私安全的技能／技术栈面板替换方案 A 的肖像资料卡。
- 将方案 A 的 About 内容折叠进 Hero，不再出现独立“关于”或“个人资料”章节。
- 不采用方案 B，也不采用方案 C 的深色全站主题、终端网格、超大英文 Hero、位置／状态侧栏或原则卡片。

最终页面应像一份经过编辑的中文技术作品集：专业、可信、有辨识度，但不依赖个人隐私建立信任。

## 2. 页面信息架构

### 2.1 首页内容顺序

除固定导航与页脚元信息外，首页只允许出现四个一级内容区：

1. `#intro`：公开介绍（Hero）
2. `#work`：作品展示
3. `#writing`：博客
4. `#contact`：联系方式

Hero 是首页第一块内容，不是独立页面或独立路由。博客功能仍包含独立列表页与详情页。

### 2.2 访客路径

1. 在首屏理解站点所有者的技术方向、技能与技术栈。
2. 通过主按钮进入三个精选作品。
3. 从作品档案行理解成果、职责、技术和年份，并打开仓库或演示。
4. 发现近期博客，并进入博客列表或详情。
5. 通过邮箱联系，或访问 GitHub 查看更多公开代码。

页面不得设置登录门槛、弹窗、轮播图、隐藏入口或原型切换器。

## 3. 原型取舍矩阵

| 原型元素 | 最终决定 | 生产要求 |
| --- | --- | --- |
| A：暖色纸张背景 | 保留 | 作为全站主基底 |
| A：浮动浅色导航 | 保留并修改 | 导航改为介绍、作品、博客、联系，并增加 GitHub 外链 |
| A：中文衬线 Hero | 保留 | 文案必须是已确认的技术价值主张 |
| A：资料卡／肖像 | 替换 | 改为技能／技术栈面板，不展示个人资料 |
| A：机会状态、位置、数字指标 | 删除 | 不允许进入生产内容 |
| A：卡片式作品网格 | 删除 | 使用 C 的全宽档案行 |
| A：独立 About 区 | 合并 | 工作方式与技能合并进 Hero |
| A：博客分隔行 | 保留 | 首页最多三篇，列表页沿用同一语言 |
| A：深色联系页脚 | 保留 | 展示邮箱、GitHub 和版权标识 |
| C：作品档案行 | 保留并浅色化 | 保留编号、成果、职责、技术栈、年份、外链 |
| C：深色终端主题与网格 | 删除 | 不进入全局视觉系统 |
| C：巨大英文 Hero | 删除 | 以 A 的中文编辑式标题为准 |
| C：原则卡片 | 删除 | MVP 不新增第五个首页内容区 |
| B：Bento 布局 | 删除 | 不进入最终实现 |
| PrototypeSwitcher | 删除 | 生产环境只有一个最终版本 |

## 4. 视觉系统

### 4.1 色彩

| Token | 色值 | 用途 |
| --- | --- | --- |
| Paper | `#F4F0E7` | 页面主背景，来自方案 A |
| Surface | `#FBF9F3` | 导航、技能面板、悬浮表面 |
| Ink | `#17211B` | 主文字、主按钮、联系区背景 |
| Forest | `#326A4A` | Hero 强调、链接悬停、激活状态 |
| Signal | `#DFFF78` | 少量焦点与状态提示 |
| Body Muted | `#5F6760` | 辅助正文 |
| Meta Quiet | `#676D67` | 编号、日期、元数据 |
| Rule | `rgba(23, 33, 27, 0.15)` | 分隔线与边框 |

> 修订说明：Body Muted 与 Meta Quiet 原稿分别为 `#687069`／`#8B908C`，
> 在 Paper 背景上对比度不足 AA（4.49／2.86）。依据本章 §7「文本和控件满足
> WCAG AA 对比度」上调为 `#5F6760`（5.14:1）／`#676D67`（4.66:1）。

Signal 只能用于焦点、箭头或微小状态，不得成为大面积背景。作品区必须使用 A 的浅色系统，不得复制 C 的黑底荧光绿主题。

### 4.2 字体

- 页面级标题与章节标题使用中文系统衬线字体栈，拉丁字符回退为 `Georgia`。
- 正文、导航、按钮和元数据使用系统无衬线字体栈。
- 技术名称和短标签可以使用英文；承载实际意思的标题、摘要和行动文本以中文为主。
- Hero 标题使用 `clamp(54px, 6.4vw, 92px)` 的视觉尺度，移动端最大约 54 像素。
- 正文为 16–18 像素，行高 1.65–1.8。
- 不加载远程字体，避免字体服务阻塞首屏。

### 4.3 布局与形状

- 内容最大宽度 1180 像素。
- 桌面端水平留白至少 20 像素；620 像素以下为 14 像素。
- 主要断点为 900 像素和 620 像素。
- 小控件使用约 12 像素圆角，浮动导航约 18 像素，技能面板可使用约 28 像素。
- 主要按钮使用胶囊形，触控高度至少 44 像素。
- 内容组织优先使用留白和分隔线，避免多层卡片嵌套。

## 5. 组件规格

### 5.1 浮动导航

- 延续 A 原型：桌面端固定在视口顶部 16 像素，居中，最大宽度 1180 像素，半透明浅色背景并带轻微模糊。
- 左侧展示可公开的站点标识，不要求真实姓名。
- 中间入口为介绍、作品、博客、联系，对应首页四个锚点。
- GitHub 是清晰标注的外部链接；联系按钮打开已验证邮箱或滚动到联系区。
- 720 像素以下隐藏中间导航，保留站点标识、GitHub 与联系入口；不得用不可操作的汉堡图标占位。
- 不显示登录、注册、聊天、在线编程或计划入口。

### 5.2 公开介绍（Hero）

- 延续 A 原型的不对称双栏和首屏高度感，桌面端顶部留白约 155 像素。
- 左栏顺序：技术栈眉题、中文价值主张、第一人称简短技术介绍、主次行动按钮。
- 主按钮文案为“查看精选作品”，滚动到 `#work`。
- 次按钮文案为“给我发邮件”，打开已验证邮箱。
- GitHub 链接必须在 Hero 或固定导航中首屏可见。
- 右栏是技能／技术栈面板，视觉上继承 A 资料卡的浅色悬浮表面，但内容只按后端、前端、交付分组展示技术名称。
- 技能面板不得使用头像、位置、时区、机会状态、简历、经历、工作年限、百分比熟练度或未经验证的数字指标。
- 900 像素以下改为单栏，先文案与行动，再技能面板。

### 5.3 作品展示

- 区块标题沿用原型语气：“不只展示代码，也讲清楚它解决了什么。”最终文案可以等义调整。
- 固定展示三个真实精选作品，不提供站内作品详情页。
- 每个作品采用从 C 原型转译而来的全宽档案行，不使用 A 的图片卡片网格。
- 桌面端信息顺序：编号；标题与一句成果；职责、技术栈、年份；外部行动入口。
- 一个作品可有“代码仓库”和“在线演示”两个明确文字入口；不得只用无说明箭头区分不同目标。
- 悬停仅使用轻微浅色表面或文字颜色变化，不让整行在存在多个目标时成为含义不明的链接。
- 900 像素以下改为堆叠布局；职责和技术栈必须移动到标题下方，不得像 C 原型那样隐藏。
- 不展示虚构客户、未经验证的指标、库存截图或装饰性数据看板。

### 5.4 博客

- 首页最多展示三篇近期博客，沿用 A 原型的分隔行布局。
- 每行包含发布日期、标题、预计阅读时间和明确的阅读入口。
- 首页区块提供“查看全部博客”入口。
- 独立博客列表页沿用同一列表语言；详情页使用克制正文宽度，优先保证长文阅读。
- MVP 不包含标签、分类、搜索、评论、目录、推荐文章或访问量。

### 5.5 联系方式

- 延续 A 原型的 Ink 深色收尾，但内容作为首页第四区 `#contact`。
- 使用一句直接的中文收尾文案，展示已验证邮箱和 GitHub 链接。
- 邮箱和 GitHub 必须是带名称的可点击链接，不能只是不可交互的文本。
- 展示版权标识；不展示位置、电话、微信二维码或其他未批准信息。
- 不提供联系表单，不收集访客信息。

## 6. 交互与状态

- 默认过渡时长 160–220 毫秒，只改变颜色、透明度或轻微位移。
- 尊重 `prefers-reduced-motion`；关闭动效后内容仍完整可用。
- 不使用视差、滚动劫持、自动播放、自定义鼠标指针或主题切换器。
- Render API 冷启动时，静态导航和四区骨架立即出现。
- 三秒仍未获得内容时，说明免费内容服务正在启动，通常可能需要约一分钟。
- 幂等请求在不超过 75 秒的窗口内有限重试，最终失败后显示手动重试按钮。
- 不存在的博客和未知路由使用站内 404，并提供返回路径。

## 7. 响应式与无障碍

- 390 像素移动端到宽屏桌面端均不得出现横向滚动。
- 导航、按钮、作品链接、博客链接和重试按钮尽量达到 44 × 44 像素触控目标。
- 每个页面只有一个页面级 `h1`，四个首页区域使用语义化地标与标题层级。
- 所有交互元素保留可见键盘焦点；仅箭头图标必须具有可访问名称。
- 文本和控件满足 WCAG AA 对比度。
- 外部链接清楚标明目标，并采用安全的新窗口行为。
- Markdown 正文禁用原始 HTML；有意义的图片必须有替代文本。

## 8. 内容规则

- 中文优先，表达直接、具体。
- 公开介绍只描述技术方向、技能、技术栈和经过确认的工作方式。
- 作品使用主动语态，优先说明构建了什么、解决了什么、承担了什么。
- 原型内的 HXC、邮箱、年份、项目标题、指标和文章标题全部视为示意内容，只有经站点所有者确认后才可上线。
- 任何必填真实内容未就绪时阻止发布，不用虚构信息填空。

## 9. 视觉验收

- 页面整体可明确识别为方案 A 的浅色编辑式方向。
- 作品区可明确识别为方案 C 的横向档案结构，但已适配浅色系统。
- Hero 右侧不存在个人资料卡，只存在技能／技术栈面板。
- 首页只有公开介绍、作品展示、博客、联系方式四个一级内容区。
- GitHub 在首屏和联系区均有清晰入口。
- 桌面端和 390 像素移动端无横向溢出。
- 冷启动、失败、空内容和 404 与主视觉保持一致。
- 页面不存在原型切换器、淘汰方案或旧功能入口。

## 10. 明确延期

- 独立个人资料页，以及位置、机会状态、简历、肖像和经历时间线。
- 管理后台、数据库内容编辑和 CRUD。
- 作品详情页、媒体画廊、复杂插画和动效系统。
- 博客标签、分类、搜索、评论、富文本编辑、上传和分析。
- 深色模式、主题切换和完整国际化。
- 独立域名与 ICP 备案。
